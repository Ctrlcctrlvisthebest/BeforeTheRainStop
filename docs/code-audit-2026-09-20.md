## 已修复的问题

| 问题与触发条件 | 调整 |
| --- | --- |
| 出生时支撑平台固定写为编号 0；自制地图的第一个平台若是远处渡台，角色首帧会被错误带动 | 按每位玩家实际出生坐标和平台顶面确定支撑平台 |
| `newGame` 接受字符串形式的关卡编号，甚至会取到数组原型属性 | 关卡编号必须是有效整数 |
| 时间步为 `NaN`、无穷大或非正数时会污染物理状态 | 忽略无效时间步，不改动游戏状态 |
| 编辑器关闭渡台运动后，乘坐或换乘引导仍引用已静止的平台 | 清理相关失效引导，保留其他路线，并继续支持撤销 |
| 一次浏览器存储写入失败后，下一次通关若没有刷新当前关卡最佳成绩，其他关卡积压的成绩不会补存，且界面可能误报保存成功 | 比较整个合并成绩集，补写所有未保存的最佳成绩；写入仍失败时保持失败标记 |
| 排行榜返回 `entries: null`、错误姓名类型等数据时，React 渲染可能崩溃 | 在网络层验证榜单及条目结构，由已有错误界面处理异常响应 |
| 输入法组合输入可能被识别成游戏移动、跳跃或重开 | 忽略组合输入的按下事件，正常处理松开事件，避免已有按键卡住 |
| 退出游戏或试玩时只释放模型，场景灯光持有的阴影缓冲未释放 | 释放完整场景中的灯光及阴影资源，再释放渲染器 |
| WebSocket 后端异步请求未被 `await`，拒绝时绕过外层错误处理 | 等待后端请求，让异常进入统一 JSON 错误响应 |
| 合法的 Content-Type、Bearer 大小写形式被拒绝，同时伪装 MIME、裸令牌可能被接受 | 精确验证 JSON MIME，支持标准大小写，复用严格 UUID 令牌校验 |
| 成绩重试会把房间到期闹钟向后推迟；延迟闹钟期间模拟仍可能继续 | 闹钟取较早的到期/重试时间，模拟启动和每次更新都检查到期；未上传成绩仍保留并继续重试 |
| 内部成绩对象的姓名数组、ID、参与者和达成时间检查不足，可能写入畸形排行榜记录 | 入库前验证元数据，非法记录不写入 SQLite |
